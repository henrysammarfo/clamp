# CLAMP Frontend API Contract v0.2

This document describes the current FastAPI implementation. `docs/openapi.json` is the machine-readable source of truth.

## Conventions

- The local API normally runs at `http://localhost:8000`.
- Request and response bodies use `application/json`.
- Money uses decimal values. The API accepts JSON numbers or strings, but **serializes money as strings** to preserve precision.
- Datetimes are ISO 8601 strings. `expires_at` must include a timezone and is normalized to UTC.
- Decisions are `ALLOW`, `BLOCK`, or `NEEDS_HUMAN`.
- IDs are UUID strings generated by the backend.
- An `ALLOW` immediately deducts the purchase amount from `remaining_budget`.
- `NEEDS_HUMAN` deducts nothing until approval succeeds.
- `POST /api/decisions` is **not idempotent**. The UI must prevent double-submit and must not automatically retry it.
- Submit `audit_payload` to Base Sepolia exactly as returned. Call `/chain` only after the transaction is confirmed.

The examples below use stable illustrative UUIDs and timestamps. Kiln controls the exact text inside `structured_request.item` and `structured_request.purpose`.

## Mandates

### `POST /api/mandates`

Request:

```json
{
  "name": "Office supplies mandate",
  "purpose": "Office supplies",
  "total_budget": "100",
  "currency": "USD",
  "allowed_merchants": ["Amazon"],
  "expires_at": "2026-10-01T12:00:00Z",
  "human_approval_threshold": "80"
}
```

Response: `201 Created`

```json
{
  "id": "11111111-1111-4111-8111-111111111111",
  "name": "Office supplies mandate",
  "purpose": "Office supplies",
  "total_budget": "100",
  "remaining_budget": "100",
  "currency": "USD",
  "allowed_merchants": ["Amazon"],
  "expires_at": "2026-10-01T12:00:00Z",
  "human_approval_threshold": "80",
  "status": "ACTIVE",
  "created_at": "2026-09-29T03:00:00Z"
}
```

### `GET /api/mandates`

Response: `200 OK`. Newest mandates are first.

```json
[
  {
    "id": "11111111-1111-4111-8111-111111111111",
    "name": "Office supplies mandate",
    "purpose": "Office supplies",
    "total_budget": "100",
    "remaining_budget": "35",
    "currency": "USD",
    "allowed_merchants": ["Amazon"],
    "expires_at": "2026-10-01T12:00:00Z",
    "human_approval_threshold": "80",
    "status": "ACTIVE",
    "created_at": "2026-09-29T03:00:00Z"
  }
]
```

### `GET /api/mandates/{id}`

Response: `200 OK`, with the same mandate object shape shown above. A previously ACTIVE mandate is persisted and returned as `EXPIRED` when read after `expires_at`.

Missing ID: `404 Not Found`

```json
{"detail":"Mandate not found"}
```

## Decisions

### `POST /api/decisions`

Request:

```json
{
  "mandate_id": "11111111-1111-4111-8111-111111111111",
  "request": "Buy a keyboard from Amazon for $65."
}
```

Response: `201 Created`

```json
{
  "id": "22222222-2222-4222-8222-222222222222",
  "decision_id": "22222222-2222-4222-8222-222222222222",
  "mandate_id": "11111111-1111-4111-8111-111111111111",
  "original_request": "Buy a keyboard from Amazon for $65.",
  "structured_request": {
    "merchant": "Amazon",
    "amount": "65",
    "currency": "USD",
    "item": "keyboard",
    "purpose": "Office supplies"
  },
  "decision": "ALLOW",
  "matched_rule": "all_checks_passed",
  "reason_code": "POLICY_ALLOW",
  "reason": "The purchase satisfies every mandate rule.",
  "timestamp": "2026-09-29T03:01:00Z",
  "blockchain_network": null,
  "tx_hash": null,
  "audit_payload": {
    "decision_id": "22222222-2222-4222-8222-222222222222",
    "mandate_id": "11111111-1111-4111-8111-111111111111",
    "purchase_request_hash": "0x0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef",
    "decision": "ALLOW",
    "reason_code": "POLICY_ALLOW",
    "timestamp": "2026-09-29T03:01:00Z"
  }
}
```

The LLM only constructs `structured_request`. Deterministic Python evaluates the mandate and sets `decision`, `matched_rule`, `reason_code`, and `reason`.

This operation is not idempotent: repeating it calls Kiln again, creates another receipt, and may deduct budget again. Disable the submit control while pending and do not configure automatic mutation retries.

### `POST /api/decisions/{id}/chain`

Call only after the Base Sepolia transaction is confirmed. A `NEEDS_HUMAN` decision must be approved first.

Request:

```json
{
  "network": "base-sepolia",
  "tx_hash": "0xabc123"
}
```

Response: `200 OK`. It returns the complete receipt, with these fields changed:

```json
{
  "blockchain_network": "base-sepolia",
  "tx_hash": "0xabc123"
}
```

The actual response is not a partial object; it is the entire Decision Receipt shown under `POST /api/decisions`.

## Errors

The API uses FastAPI's standard JSON error envelope.

| Endpoint or condition | Status | Exact body |
|---|---:|---|
| Unknown mandate | 404 | `{"detail":"Mandate not found"}` |
| Unknown decision | 404 | `{"detail":"Decision not found"}` |
| Approve an ALLOW/BLOCK/already approved receipt | 409 | `{"detail":"Only NEEDS_HUMAN decisions can be approved"}` |
| Approval after mandate expiry/revocation or insufficient budget | 409 | `{"detail":"Mandate is no longer active or has insufficient budget"}` |
| Chain a NEEDS_HUMAN receipt | 409 | `{"detail":"Decision must be approved before blockchain attachment"}` |
| Attach a second chain transaction | 409 | `{"detail":"Blockchain transaction is already attached"}` |
| Missing local Kiln key | 502 | `{"detail":"KILN_API_KEY is not configured"}` |
| Kiln transport/API failure | 502 | `{"detail":"Kiln request failed: <upstream error>"}` |
| Empty Kiln completion | 502 | `{"detail":"Kiln returned an empty response"}` |
| Malformed or schema-invalid Kiln JSON | 502 | `{"detail":"Kiln returned malformed or invalid purchase JSON"}` |

Request validation returns `422 Unprocessable Entity`. The exact entries vary by invalid field; this is the actual body for an empty decision request:

```json
{
  "detail": [
    {
      "type": "missing",
      "loc": ["body", "mandate_id"],
      "msg": "Field required",
      "input": {}
    },
    {
      "type": "missing",
      "loc": ["body", "request"],
      "msg": "Field required",
      "input": {}
    }
  ]
}
```

## Frontend transaction sequence

1. Create or select an ACTIVE mandate.
2. Disable the decision submit button and call `POST /api/decisions` exactly once.
3. If `BLOCK`, display the receipt; it is final and may be anchored.
4. If `NEEDS_HUMAN`, show approval UI and do not submit to the chain yet.
5. After successful approval, use the newly returned receipt and its updated `audit_payload`.
6. Submit that exact payload to the Base Sepolia contract.
7. Wait for transaction confirmation.
8. Attach `{ "network": "base-sepolia", "tx_hash": "..." }` through `/chain` exactly once.
